# holdem-pk

由 CLI Agent 主持的六人／八人终端德扑框架。Python 是规则裁判，Codex 是主持人和五名或七名对手；没有模型 API 层，没有嵌套 CLI 调用，没有第三方依赖。

## 在 Codex 中玩

使用 Python 3.10+，在此目录启动 Codex，说：

> 读取 AGENTS.md，开始六人德扑。

Codex 按协议调用 `python3 -m holdem`，展示文本牌桌，轮到你时等待输入。关闭会话后可从本地存档恢复。本阶段只验证 Python 工具；Codex 实际交互仍需试玩验收。

## 文件

- `AGENTS.md`：Agent 对战、主持、工具使用协议。
- `holdem/__main__.py`：牌型比较、下注状态机、边池结算、CLI 与本地 JSON 存档。
- `tests/test_game.py`：规则与完整对局验证。
- `.holdem/`：运行时私有存档，不提交。

运行 `python3 -m unittest discover -s tests -v` 验证。`python3 -m holdem --help` 查看工具入口。

## 高级终端牌桌

默认 `python3 -m holdem table` 保持原来的纯文本输出。可在真实终端中启用彩色牌桌：

```bash
python3 -m holdem table --style rich
python3 -m holdem table --style rich --width 120
python3 -m holdem table --style rich --color never
```

高级模式使用独立玩家面板、四色花色、行动者高亮及公共牌区域。120 列以上的六人桌采用环桌布局；80–119 列采用两列面板；40–79 列采用单列面板。完整行动记录和结算保留在下方。此模式只使用标准库，无需安装 Rich。

`--color auto|always|never` 默认 auto：仅真实终端自动启用颜色，遵守 `NO_COLOR` 和 `TERM=dumb`；always 可显式覆盖。`--width` 最小 40；自动检测不足 40 列时回退纯文本。`--seat` 和全局 `--state` 仍可使用。

高级牌桌是一次性只读快照，不会自动刷新或执行动作。聊天代码块不保证呈现 ANSI 颜色，Agent 默认仍展示纯文本；在终端重跑命令可查看最新牌局。隔离工作树默认使用各自的 `.holdem/state.json`，查看其他目录的牌局需明确指定 `--state`。

MVP 为你加五名角色对手，固定 5/10 盲注、1000 起始筹码，支持弃牌、过牌、跟注、加注与全押。按钮轮转，破产玩家坐出，存档存在时 new 拒绝覆盖。需要独立新场次时，在另一个工作目录通过 PYTHONPATH 指向本仓库运行工具。

重要边界：同一个 Agent 看过多个视角，无法严格隔离底牌；这版用于验证可玩闭环。多个不足额全押的累积重开加注尚不支持。当前没有常驻 TUI，牌桌由 Agent 在终端排版；暂未提供 Claude Code 专用入口或验收。后续优先根据试玩修正规则与交互，再考虑独立角色上下文和专门 TUI。

## 文本牌桌与行动记录

`python3 -m holdem table` 只读展示当前用户牌桌，包括位置、状态、剩余筹码、本轮下注、本手投入，以及按阶段分组的完整行动过程。`view` 仍返回 JSON，供 Agent 决策；工具不调用模型。牌面统一为 `10 ♣ / A ♥`。

新手牌记录盲注、行动实际投入和下注总额、行动后底池、公共牌、轮次结束、退款与结算。结束后显示本手与累计盈亏、主池和边池。旧存档可直接恢复，但历史事件与盈亏基线缺失时显示不完整或未知，不回填推测记录；下一手开始完整记录。

可用全局参数 `--state /绝对路径/state.json` 指定已有存档，例如在隔离 worktree 中查看主目录存档；`table` 为只读操作。

旧四人存档在本手结束后运行 `python3 -m holdem expand`，保留原筹码，新增指南针与闪电各买入 1000，然后 `next` 开始六人牌局；进行中的手牌拒绝扩桌。

## 对话高级牌桌

`python3 -m holdem table --style chat` 输出适合聊天代码块的高级牌桌，不依赖 ANSI 颜色；`--color` 对此样式无影响。默认固定 120 列，支持 `--width`。120 列及以上六人桌保留环桌，80–119 列采用双列，40–79 列采用单列，低于 40 列提示并回退纯文本。

玩家面板以双线框标识用户、粗线框标识其他行动者，并显示文字状态、位置、剩余筹码、本轮下注、本手投入。可见牌使用独立牌框及花色名称；对手底牌保持隐藏。完整行动及结算保留。该命令只读，不改变牌局。

跨工作树展示已有牌局时使用 `python3 -m holdem --state /绝对路径/state.json table --style chat`。主持时原样展示输出，不手工重排。聊天字体可能影响字符宽度，最终效果应以对话截图检查。

对话样式使用固定玩家图标（🧑 / 🪨 / 🦊 / 🌊 / 🧭 / ⚡ / 🐱 / ⛵），🃏 标记牌区，💰 标记筹码与底池，🟢 / ⌛ / ❌ / 🔥 / 💤 / 🏁 标记行动、等待、弃牌、全押、坐出和结束。🎮 标记操作区，📜 标记行动记录，🏆 标记结算；所有图标均附文字，不只依靠颜色区分。

## 只读牌桌辅助器

开启辅助后，聊天先完整展示牌桌代码块，再在代码块外原样展示独立 Markdown 面板：

```bash
python3 -m holdem table --style chat
python3 -m holdem assist --format markdown
```

面板按决策顺序排列：**具体首选与信心 → 备选 → 首选的获胜机会 → 各动作概率、收益和风险 → 对手关键威胁 → 原因拆分**。
有人未回应也会给出具体建议。优先比较预计净收益；收益差异小于比较误差时减少投入，再比较亏损风险。估计稳定性较低时保留“低信心推荐”，不退回“不确定”。只有不具备行动资格或数据无效时停止行动建议。

```bash
python3 -m holdem assist --format markdown --detail
python3 -m holdem assist --format text --width 64
python3 -m holdem assist --seat 3 --samples 10000
python3 -m holdem table --assist
python3 -m holdem table --style chat --assist-detail --width 80
```

独立 `assist` 默认输出 Markdown，`--detail` 展开更多公开证据、完整威胁组合、关键来牌及反加风险。`table --assist` / `--assist-detail` 保留，以紧凑文本随牌桌输出，遵守 `--width`。
支持六人／八人、标准／老赌鬼模式、任意合法观察座位以及旧存档。全局 `--state /绝对路径/state.json` 需在子命令前指定；跨工作树查看同一局时，两个命令都要传入该路径。辅助关闭时牌桌输出保持原样。

**威胁覆盖：**枚举与本人底牌、公共牌无冲突的全部对手组合，按能击败本人的牌型类别汇总，避免两个相同葫芦示例挤掉顺子风险。顺子展示关键点数组合，如 Q＋9 / 9＋7。`public-actions-v2` 区分公共对子、弱对子、顶对、超对、弱两对、强两对、三条以及更强成牌，结合底牌贡献、踢脚、听牌和下注尺度更新范围。威胁占比是各席候选范围中的估计，不是联合事件概率或已知持牌。

**动作预测：**合法候选包括弃牌、过牌／跟注以及半池、满池、全押，金额限制在合法范围内并去重，最多三个下注候选。每个动作使用相同的联合底牌／未来牌样本与响应随机数，以公平比较金额差异。
当前轮对手按其候选牌力、跟注价格、位置、在局人数和公开压力选择弃牌、跟注或反加。响应接口只能接收该席候选底牌和公开信息，不能看到用户真实底牌、其他席样本底牌或未来公共牌。继续留场者因其响应被重新筛选；大额下注通常更容易逼弃，也更容易只被强牌跟注，不能仅看获胜率推荐全押。

模拟使用规则引擎的内存下注转换，不发出下一街公共牌、不读写存档。当前轮最多一次对手加注／反加，之后仅跟／弃；遇反加后按相同可见行动路径汇总跟注和弃牌收益，再选择应对，不能逐个样本看隐藏结果择优。路径有效样本不足 30 时，采用只依赖本人可见牌力和价格的保守继续规则，并降低信心。后续街假设无额外下注。

**概率与收益：**单池总获胜概率等于直接拿池概率加摊牌独赢概率，平局另列。主池与边池分别展示“形成且本人可争夺”的概率，以及该条件下的获胜／平局概率，不合并成混杂的整手胜率。退款不算获胜。净收益从当前决策点起计算，包含反加后的追加成本；既往投入不重复扣除，平分奇数筹码按规则引擎的庄位顺序分配。亏损概率指从当前决策点继续投入后的净损失风险。

**可信度边界：**范围与响应模型是版本化的未校准人工规则，信心仅表示模型内比较的稳定性，不是实际获胜率校准或 GTO 证明。`--samples` 为起始抽样数（100–100000，默认 2000）；有效样本不足 100 时自动倍增，上限 max(起始数,10000)，总上限 100000。仍不稳定时保留低信心的具体建议。增加样本不能消除行为假设误差。默认面板与详情均不罗列公式、权重和抽样统计。

辅助仅接收白名单快照：本人底牌、已发公共牌、公开筹码／位置／行动及本人回合合法选项。对手真实底牌、真实牌堆、烧牌、未来公共牌和内部风格配置均不传入。历史不完整时按随机范围参照，下注状态采用公开筹码和合法选项的保守恢复，并降低推荐信心。公开事件重放只用当时可见信息，属于模型内解释。结果使用稳定种子可复现；辅助不执行真实动作、不调用网络或模型 API。这是接口隔离，不是严格系统权限隔离。

## 老赌鬼模式

```bash
python3 -m holdem --state .holdem/gambler.json new --players 8 --mode gambler
python3 -m holdem --state .holdem/gambler.json table
```

`--mode` 仅在 `new` 时设置，默认 `standard`。请为新桌指定不存在的独立路径；旧存档按标准模式兼容，进行中的牌桌不受影响。实际工作产物存档请使用带本机微秒时间戳的唯一名称。

赌鬼模式由主持 Agent 按 `GAMBLER.md` 和当前席 view 返回的 `decision_profile` 执行，包含七席侧重、强牌设局、有条件诈唬和公开行动观察。Python 不运行自动机器人，也不保证模型执行质量。模式不提供严格信息隔离，难度需实际试玩验证。

## 八人桌与对手改名

`new --players 8` 创建八人桌，默认仍为六人；`rename <全部对手昵称>` 按座位顺序修改五个或七个对手昵称，保留牌局进度。高级样式的八人桌在 80 列及以上使用双列面板，更窄时使用单列。

`recover-unacted` 保留旧版未行动错位手牌的安全恢复功能，执行前自动生成带本机微秒时间戳的备份。
