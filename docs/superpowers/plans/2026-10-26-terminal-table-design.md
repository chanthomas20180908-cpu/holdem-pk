# 高级终端牌桌设计与实施方案

**目标：** 默认纯文本输出保持兼容，通过 `table --style rich` 显示具有独立座位、公共牌卡片、花色颜色和行动高亮的终端牌桌。

**架构：** 保留现有规则、存档、`view()` 信息过滤及 `display.render()`；新增只消费过滤视图的独立高级渲染器。第一版为一次性只读快照，与现有 Agent 主持流程配合。

**技术：** Python 3.10+ 标准库、ANSI SGR 颜色、Unicode 边框；不新增第三方依赖。`rich` 是显示风格名，不代表引入 Rich 库。

## 1. 使用方式

```bash
# 默认输出与现在一致
python3 -m holdem table

# 高级终端牌桌
python3 -m holdem table --style rich

# 无颜色的高级布局，适合保存、截图文字或不支持颜色的终端
python3 -m holdem table --style rich --color never

# 显式启用 ANSI，适合支持 ANSI 的输出接收端
python3 -m holdem table --style rich --color always

# 在新工作树查看主目录的同一个存档
python3 -m holdem --state /Users/test/code/holdem-pk/.holdem/state.json table --style rich
```

新增参数只属于 `table`：`--style plain|rich`，默认 `plain`；`--color auto|always|never`，默认 `auto`；`--width N`，可选，最小 40，控制布局宽度以便测试和截屏。原有 `--seat` 保留。

`plain` 始终走原渲染器，不添加 ANSI、重排或新字段。`rich` 下 `auto` 仅在 stdout 为 TTY、TERM 非 dumb 且未设置 NO_COLOR 时启用颜色；显式 `always/never` 优先。尺寸自动检测使用 `shutil.get_terminal_size(fallback=(100, 30))`。

## 2. 视觉方向

采用深色终端友好的牌室风格：边框低亮度、底池醒目、玩家区块有清晰间距，避免大面积背景色。支持浅色终端，以终端默认前景色作为正文，不强制黑底。

- 中央：手数、阶段、公共牌、底池，以及当前行动人。
- 六席：每人单独边框，显示座位号、名字、庄位/小盲/大盲、状态、剩余筹码、本轮下注、本手投入、底牌或背面。
- 用户固定下方，其他玩家按相对座位顺序围绕牌桌，庄位标记随规则轮转，座位不随按钮移动。
- 玩家顺时针顺序为 0→1→2→3→4→5；从用户下方开始，依次是左下、左上、上方、右上、右下。
- 行动者使用亮青色边框及 `▶ 行动中`；用户使用 `你` 明确标识；全押显示黄色 `全押`；弃牌使用低亮度并保留可读文字；筹码归零且本手未参与者显示 `坐出`。不能只靠颜色传达状态。
- 红桃红色、方块蓝色、梅花绿色、黑桃默认前景色，采用四色牌便于区分；文字始终保留花色符号。赢取底池的结算金额为绿色，亏损为红色，同时保留正负号。
- 手牌与公共牌使用小卡片边框，点数与花色之间有一个半角空格，多张牌以 ` / ` 分隔；未公开底牌为 `▒▒`，未发公共牌为空槽，不伪造牌值。

以下仅为结构线框，所有变量为占位，不是实际牌局或结算：

```text
第 {手数} 手 · {阶段}                           盲注 5 / 10

                         ┌─ 3 浪潮 ───────┐
                         │ 筹码 / 状态    │
                         │ 本轮 / 本手    │
                         │ ▒▒ / ▒▒        │
                         └────────────────┘
 ┌─ 2 猎狐 ───────┐                              ┌─ 4 指南针 ─────┐
 │ 筹码 / 状态    │                              │ 筹码 / 状态    │
 │ 本轮 / 本手    │      公共牌：五个卡片槽        │ 本轮 / 本手    │
 │ ▒▒ / ▒▒        │      底池：{实际金额}          │ ▒▒ / ▒▒        │
 └────────────────┘      行动：{玩家名}            └────────────────┘
 ┌─ 1 岩石 ───────┐                              ┌─ 5 闪电 ───────┐
 │ 筹码 / 状态    │                              │ 筹码 / 状态    │
 │ 本轮 / 本手    │                              │ 本轮 / 本手    │
 │ ▒▒ / ▒▒        │                              │ ▒▒ / ▒▒        │
 └────────────────┘                              └────────────────┘
```

实际卡片内容示例为 `A ♠ / 10 ♥`。在卡片边框内同样保留空格和分隔符；ANSI 样式不能插入点数与花色之间的那个半角空格。

## 3. 窄终端与完整信息

- 宽度 ≥120 列：环桌布局，六席分隔，中央公共牌与底池。
- 80–119 列：两列玩家面板，公共牌位于顶部、用户面板突出显示；不强塞环桌以免信息过密。
- 40–79 列：单列面板，公共牌改用紧凑行，保留全部字段。
- 实际宽度 <40 列：退回现有纯文本格式并提示增加窗口宽度，不承诺原格式在极窄终端对齐。
- 四人旧存档根据人数布局，不创建虚构玩家；`--seat` 改变观察视角和底牌可见性，环桌随观察者旋转，只有座位 0 标注“你”。
- 面板按显示宽度排版，ANSI 转义不计列宽；中文按宽字符计数。不用 emoji，降低字体宽度差异。花色符号在常见终端仍可能存在字体差异，需实机检查。
- 完整行动记录置于牌桌下方，沿用现有事件语义，不能仅展示最近几条。输出可以自然滚动，不截断历史来适应屏高。
- 旧存档仍显示“历史不完整/未知”。结算分别展示主池、边池、分得底池和退款；结束后的当前底池为零时，不能把它标作本手累计奖池。
- 结算中按视图允许公开的底牌展示，不因美化增加隐藏信息；牌型名称作为后续增强，本期不增加胜率、听牌或策略建议。

## 4. 与现有主持流程配合

第一版保留 `view → act → table` 流程，由 Agent 决定五名角色对手的行动，用户仍在聊天中输入自然语言。显示参数不存入游戏状态，也不触发下注、发牌或下一手。

高级模式在真实终端中直接运行才显示颜色。工具捕获的输出、聊天代码块不能保证渲染 ANSI；因此 Agent 默认继续按协议展示纯文本牌桌。用户可在终端执行高级命令查看同一份存档，每次命令显示当时快照。不得宣称它会自动刷新。

后续若需要“终端一直打开且自动刷新”，另做 `watch` 只读观察模式，检测存档替换后重绘。它不执行 AI、不调用模型 API、不创建随机对手。全屏交互输入及 Agent 通信需要另行设计，不纳入这版显示功能。

## 5. 代码边界

| 文件 | 职责 |
|---|---|
| `holdem/display.py` | 原纯文本渲染保持兼容；复用 `cards`、`event_text`，必要时提取共用历史及结算格式 |
| `holdem/terminal.py`（新增） | ANSI 样式、可见列宽、边框、卡片、面板布局和 `render(view, seat=0, *, width=100, color=False) -> str` |
| `holdem/__main__.py` | `table` 新参数、终端能力检测与渲染器选择；继续先调用 `view(s, seat)` |
| `tests/test_terminal.py`（新增） | 布局宽度、花色间距、隐私、终局及无副作用测试 |
| `tests/test_display.py` | 保留纯文本回归；覆盖共享格式提取后的兼容性 |
| `README.md` / `AGENTS.md` | 命令说明、真实终端显示限制和默认主持行为 |

高级渲染器不接受原始 state，不读取文件、不访问牌堆、不改变视图。CLI 是唯一的加载和渲染分派入口。仍使用单写者存档规则。

## 6. 实施拆分与验收

- [ ] **任务一：渲染基础。** 新建 `terminal.py` 的可见宽度、填充、四花色样式、卡片及玩家面板。固定视图测试中文、`10`、四色牌、关闭颜色和 ANSI 去除后的对齐；输入视图渲染前后深比较相同。
- [ ] **任务二：牌桌组合。** 实现 120/100/60 列布局以及四人、六人和视角旋转；复用完整事件与结算语义。测试翻牌前、四街、弃牌、全押、坐出、边池、平分、退款及旧存档。断言未公开底牌字符串不出现在输出中。
- [ ] **任务三：CLI 接入。** 添加参数与颜色策略。通过子进程和临时存档验证默认 `table` 与原渲染器逐字一致，`view` 仍为可解析 JSON；`table` 执行前后存档字节与修改时间均不变。验证非 TTY、NO_COLOR、TERM=dumb 与显式覆盖行为，以及非法宽度报错。
- [ ] **任务四：实机验收与文档。** 在 macOS 终端深浅主题下检查 120/100/60 列、中文和四色花色；检查单次打印不清屏、不进入备用屏幕、不隐藏光标。更新 README 和 Agent 使用说明，明确可选样式及快照性质。

每项任务先增加对应行为测试，再实现，完成后运行对应测试。最终回归：

```bash
python3 -m unittest discover -s tests -v
```

验收重点：默认行为零变化；六席可独立辨认；用户底牌与公共牌醒目；颜色关闭后仍可理解状态；记录与结算不丢失；所有牌面格式符合项目协议；不增加信息泄露或状态变更。
